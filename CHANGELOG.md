# Changelog

## Unreleased

- Resume publication after an imported public edit even when the private copy has changed since. An edit counts as imported when a three-way merge from the last published version shows the export already contains it, or when its public commits are recorded in the private source. A blocked publication names the file and the commits to record, and the daily job logs the cause of a failure while its status file keeps the fixed message.
- Run the weekly maintainer review inside Claude Code's OS sandbox. The review passes a `--settings` profile (`review_settings` in the host configuration, or the maintainer's audit profile) that allowlists the network, confines writes to the review checkout and listed cache paths and hides credential files, and it refuses to start unless that profile turns the sandbox on, fails without one and allows no unsandboxed commands, and when it or the user's settings exempt commands or platforms from the sandbox. Upstream checks send proxy credentials up front so Git works through the sandbox proxy.
- Back off source checks that settle nothing. A note whose source is missing or ambiguous, whose check failed or whose assessment stays unresolved waits 1, 2, 4, 8 and 16 hours, then a day, before its next attempt; an edited note, a changed checker or a requested `--note-sha` check is due at once, and a requested check updates only its own note's schedule. Waiting notes keep their counts, so a failed check still fails the job, and a cycle with nothing due reads no transcript.
- Scan transcripts incrementally for source checks too, from per-file progress in `evidence-scan.json` that keeps every completed turn; only matching a note that has no recorded turn still reads every transcript. A transcript deleted during a scan is skipped instead of failing the stage.
- Prune old skill releases and public-export builds during deployment, keeping the newest, the current and previous release, the build `bin/current` selects and anything a link, launchd job or running process uses, including a build named inside a job's command string or PATH.
- Record each sync and weekly stage's duration in its status file, and run one-shot Claude Code CLI calls with the 5-minute prompt cache; the weekly review keeps the 1-hour cache.
- Finish timed-out process cleanup on macOS when a process group's members have exited but are not yet reaped, which made `killpg` fail with EPERM.
- Fall back to the signed-in Claude subscription when the Claude API reports an exhausted credit balance or rejects the key. The fallback is recorded in `api-fallback.json` and sticks: every restricted call starts on the subscription, under its usage limit, until a day has passed or the key file changes. Capture, source-check and prompt-review status name a standing fallback, sync status lists it as a warning and the monitor alerts until the API is back. A prompt review keeps one backend for all its calls and fails, staying due, when the API stops answering mid-review. Other API failures still fail the call.
- Bill public commit-message generation to the Claude API key named by the optional `generation.api_key_file`, passed to the Claude Code CLI as `ANTHROPIC_API_KEY`. An exhausted credit balance or a rejected key falls back to the signed-in subscription and records the fallback in the optional `generation.api_fallback_file`, shared with the Python pipeline; later calls use the subscription until a day passes or the key file changes. Without a key file generation still uses the subscription.
- Scan transcripts incrementally. Capture keeps per-file progress in `capture-scan.json`: unchanged Codex and Claude Code transcripts are not reread, appended ones resume after their last completed turn, and a file that shrank, was replaced, changed before its checkpoint, or has missing or unreadable progress is scanned in full, so results match a full rescan. On one maintainer's history capture's hourly scan fell from about 19 seconds to under one; source checks still scan in full.
- Run the maintainer review, investigations and prompt review weekly on Mondays at 09:00 Asia/Tokyo again; capture and source checks stay hourly. Completion from the brief daily period carries over, a manual run for an earlier deadline never moves completion back, and the prompt-review rotation resumes after the last role reviewed.
- Run restricted model calls on per-role models chosen against the frozen prompt evaluations: extraction on Claude Sonnet 5.5, source checks on Claude Haiku 5.5, and corrections and prompt review on Claude Opus 5.5. An optional `api_key_file` sends them to the Claude API through a pinned SDK helper run under `uv`, with no tools and structured output, an append-only correction for schema limits the API cannot enforce, rate limits deferred to the announced reset and token usage logged per call; without it they run through the Claude Code CLI as before.
- Drop the note privacy checks. They rejected the model's paraphrases of its own wording, product names and dates and left notes pending. Notes, source-check summaries and corrections are now validated for structure and skill scope only, with no private-identifier, quotation, name or credential rejection; the fixed policy contract that every prompt renders, the maintainer's included, and the extract, verify and correct prompts drop their privacy instructions, and the maintainer policy no longer calls its records sanitized; source checks and corrections no longer retry with a rejection class; and investigation records, prompt candidates and job error details are no longer screened for URLs, paths or credential patterns.
- Restore transcript redaction and the export scanner, which the previous export removed, and extend both. Every model input is redacted again: transcript text for extraction, source checks and corrections, the existing notes given to extraction, and now the note under check and the original a correction replaces. Redaction runs where each model input is built, on each full text before length bounds, so the maintenance and read-only filters read the original text. It now also covers quoted, JSON-style and escaped-JSON credential assignments, prefixed, suffixed and camelCase names such as `AWS_SECRET_ACCESS_KEY`, `passwd` and `private_key` names, `github_pat_` and AWS access-key tokens, whole PEM and PGP private-key blocks, URLs of any scheme, and scp-style Git remotes, which are replaced before email addresses; it stays pattern-based, and a local path is replaced only up to its first space. The Rust and Python exporters again scan exported files and commit messages for private identifiers and credentials, with identifiers matched in any case; a commit message the scanner rejects is regenerated with an instruction to leave out local paths, host names and credentials, up to three attempts. `cargo test` runs the exporter's scan over the committed inventory, and the Python suite runs the reference scanner over the working tree.
- Treat a Claude usage-limit rejection (HTTP 429 or a rejecting rate-limit event) as deferred work rather than a failed extraction. No restricted call starts until the window's reported reset, or for 30 minutes without one; waiting work stays pending without failure backoff, and capture and source checks report a warning instead of failing. Work blocked for more than 24 hours fails the stage. Failure diagnostics now include a rejecting limit's window type and reset time.
- Decode JavaScript string literals in tool calls exactly as strict-mode JavaScript does, so a skill read written as `skills\/rust\/SKILL.md` is recognized, a saved note written with JavaScript-only escapes is still recovered, and transcript parsing emits no SyntaxWarning; only literals JavaScript rejects stay unknown. A Codex or Claude Code message without text no longer stops capture or breaks its turn, and the export scanners also reject PGP private-key blocks.
- Remove earlier weekly attempts' checkouts once an attempt is validated, so superseded attempts and validated attempts whose own cleanup failed no longer leave registered Git worktrees and scoped configs behind; registrations of checkouts deleted by hand are pruned. A checkout with uncommitted or untracked files, or with a commit main does not contain, including one only in its HEAD reflog, is kept as evidence and listed in the weekly status. A checkout that cannot be removed is reported per attempt and adds a weekly warning without failing the accepted review.
- Add opt-in live Claude Code checks (`RUN_CLAUDE_LIVE=1`). They find the CLI at `~/.local/bin/claude` or on `PATH` and fail when it is missing; the exporters remove the opt-in from their candidate checks, so publication never makes model calls.
- Run capture, source verification, prompt review, maintenance review, skill evaluations and public commit-message generation through the Claude Code CLI instead of the Codex CLI. Restricted calls load no settings, instructions, tools or MCP servers and fail closed on any tool use; the publisher no longer depends on `codex-commit`, and its `generation` configuration takes `claude_path`, `model`, `effort` and `timeout_seconds`. Skills are validated with the bundled `scripts/validate_skill.py`. Historical Codex session rollouts remain capture sources.
- Refresh Rust dependencies and CI tooling; migrate SHA-256 formatting while preserving stored hashes. Building from source now requires Rust 1.88 or newer.
- Require fresh capture and evidence results before completing maintenance jobs.
- Enforce supporting-file and source-enrollment boundaries during skill publication.
- Run Rust formatting, strict Clippy and tests before publishing managed Rust snapshots.
- Add held-out prompt evaluation and recovery proofs without changing fixed policy.
- Correct skill-review guidance and include provenance-verified UnoCSS references.
