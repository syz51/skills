# Frameworks and tooling

This is a routing guide, not a replacement API manual. Inspect package versions, scripts, lockfiles, configuration, and nearby code first. Use the bundled references below; read the relevant topics for the task. These documents supplement the shared rules without restoring rejected aesthetic or scaffolding mandates. The former standalone skills no longer activate independently. Framework API libraries are versioned source snapshots; locally maintained decision guides identify their sources and check dates. Verify selected APIs against the installed package.

For new Vue/TypeScript project choices, toolchain upgrades, or performance recommendations, read [Vue and TypeScript tooling decisions](vue-typescript-tooling.md). It connects tools and compatibility boundaries; the versioned references below remain the API manuals.

## Vue conflicts resolved by technical evidence

- Vue 3.5 supports reactive destructuring directly from `defineProps` inside `<script setup>`. Earlier versions need a compatible approach. This compiler behavior does not make arbitrary destructuring of reactive objects safe. Pass a reactive getter or ref to watchers and composables when required. [Vue documentation](https://vuejs.org/api/sfc-script-setup.html#reactive-props-destructure).
- Choose `ref`, `reactive`, and shallow primitives for the actual mutation and ownership model. Keep computed getters pure and clean up async side effects. There is no shared mandate to replace primitive `ref` calls with `shallowRef`; shallow references are useful for intentionally avoiding deep conversion. [Vue advanced reactivity](https://vuejs.org/api/reactivity-advanced.html#shallowref).
- Use version-supported macros and template refs, preserving public contracts and existing working implementations. A newer shorthand is not sufficient reason for an unrelated refactor.
